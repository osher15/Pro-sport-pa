# בדיקות — המגרש PRO

## איך מריצים

```bash
npm test          # בדיקות יחידה — ללא תלויות, פחות משנייה
npm run build     # בניית הקובץ הבודד
npm run verify    # בנייה + בדיקות יחידה
npm run test:e2e  # בדיקות דפדפן — דורש playwright
```

בדיקות היחידה רצות על `node:test` המובנה ב-Node 18 ומעלה. **אין
`node_modules`, אין `lockfile`, אין מה להתקין.** זה מכוון: בדיקה
שדורשת התקנה היא בדיקה שמישהו ידלג עליה.

לבדיקות הדפדפן בלבד:

```bash
npm i --no-save playwright@1.56.1
npx playwright install chromium
npm run test:e2e
```

## שתי שכבות, ולמה

| | יחידה | דפדפן |
|---|---|---|
| מריץ | `node:test` | Playwright + כרומיום |
| מול מה | `hm-data.js` | `Hamegrash.html` הבנוי |
| זמן | < שנייה | ~2 דקות |
| תלויות | אין | playwright |
| מוכיח | שהלוגיקה נכונה | שהלוגיקה מחוברת למסך |

`hm-data.js` נבנה כשכבה טהורה בדיוק בשביל זה. כל שאר הקבצים
באפליקציה נוגעים ב-`window` וב-DOM ואי אפשר לטעון אותם ב-Node, ולכן
כל לוגיקה שחייבת כיסוי מהיר צריכה לגור שם.

בדיקות הדפדפן קיימות כי `localStorage`, `IndexedDB` ו-DOM אמיתיים הם
הדבר היחיד שמוכיח שהשכבה הטהורה באמת מחוברת. בדיקת יחידה לא הייתה
תופסת שהאזהרה על אחסון מלא מעוצבת עם `display:none`.

## החלטות בתשתית

### השרת הסטטי

הבדיקות רצות מול `http://127.0.0.1:<פורט אקראי>/Hamegrash.html` ולא
מול `file://`, למרות שמורה פותח את הקובץ ישירות.

**למה:** דפדפן מתייחס לכל קבצי `file://` כמוצא אחד. `localStorage`
ו-`IndexedDB` נשארים משותפים גם בין `BrowserContext` נפרדים, ולכן
בדיקה אחת ירשה את הנתונים של קודמתה. במקרה שלנו זה התבטא בכך
ש-`schema.version` שנשמר בבדיקה אחת גרם להסבה לא לרוץ בבדיקה הבאה,
והיא נכשלה מסיבה שאין לה שום קשר למה שהיא בודקת.

מוצא `http` מקבל אחסון נפרד לכל הקשר. אותו קובץ בדיוק, רק דרך שרת.

### שגיאות בדפדפן מכשילות

כל `pageerror` וכל `console.error` מכשילים את הבדיקה, גם אם כל
האסרציות עברו. שגיאת JS שקטה באמצע מדידה היא בדיוק סוג התקלה שהמורה
לא יראה ואנחנו כן.

שני חריגים מוגדרים במפורש:

1. **כשל טעינת משאב** — הקובץ הבודד מושך אייקונים ו-GIFים שאינם
   ארוזים בתוכו. זה מה שקורה במכשיר בלי רשת, וזו ההתנהגות הרצויה.
2. **`suite.allow`** — חבילה שמביימת כשל בכוונה (כמו `storage.e2e.js`)
   מצהירה על דפוס ההודעות שהיא מצפה לראות. כל שגיאה אחרת עדיין מכשילה.

### מזהים נגזרים מתוכן

המיגרציה מייצרת מזהי תלמיד מ-`FNV-1a` על `כיתה|שם`, לא מ-`Date.now()`.
זה מה שמאפשר לבדיקה לכתוב `assert.deepEqual` בין שתי ריצות נפרדות —
ובאותה נשימה זה מה שהופך את המיגרציה ל-`idempotent` באמת.

## מה מכוסה

### זהות תלמיד

- מזהה גובר על שם; שינוי שם שומר על ההיסטוריה
- שני תלמידים בעלי אותו שם נשארים נפרדים, בנתונים ובממשק
- רשומה ישנה בלי מזהה עדיין נמצאת לפי שם
- מדידה חדשה נשמרת עם מזהה
- מחיקת תלמיד אינה מוחקת את מדידותיו

### הסבת סכמה

- ספירת רשומות זהה לפני ואחרי
- שם כפול ותלמיד שאינו ברשימה מסומנים ולא מנוחשים
- ריצה חוזרת לא משנה אף בית
- מזהה קיים ו-`sid` קיים לא נדרסים
- קלט פגום לא מפיל ולא נמחק
- נתונים מגרסה עתידית לא נוגעים בהם

### אחסון

- מכסה, אחסון חסום, נתון פגום וכשל לא מוכר — כל אחד מסווג נכון
- `LS.set` מחזיר `false` בכישלון
- אזהרה נראית על המסך עם מסלול הצלה
- כישלון כתיבה לא הורס את הערך הקודם

### גיבוי

- הקובץ כולל את סרטוני ה-`IndexedDB`
- סיבוב שחזור מלא מחזיר נתונים וסרטונים בגודלם המקורי
- שחזור אינו מוחק שיאים שקיימים רק במכשיר
- סרטון שחרג מהתקציב מדווח בשמו
- קובץ פגום, קובץ זר וקובץ מגרסה חדשה נדחים לפני שנוגעים בנתונים
- קובץ מוצפן אינו מכיל שם תלמיד, שם בית ספר ואף לא שמות מפתחות
- סיסמה שגויה נדחית

## CI

`.github/workflows/tests.yml`, בכל `push` ובכל `pull request`:

1. **`unit`** — `npm test` + אימות שהקובץ הבודד מסונכרן עם המקור.
2. **`e2e`** — מתקין `playwright@1.56.1` נעוץ, בונה, ומריץ.

שתיהן חוסמות. בדיקה שנכשלת ולא עוצרת merge היא בדיקה שאיש לא יתקן.

`.github/workflows/pages.yml` ממשיך לפרוס מ-`main` בלבד, ללא שינוי.

## להוסיף בדיקה

**לוגיקה טהורה** → `tests/unit/`. אם הלוגיקה לא נמצאת ב-`hm-data.js`,
שווה לשקול להעביר אותה לשם — זה מה שהופך אותה לניתנת לבדיקה.

**התנהגות במסך** → `tests/e2e/`:

```js
check("מה אמור לקרות", {"ft.roster":{…}}, async page=>{
  await page.evaluate(()=>window.HM.go("ft"));
  eq(await page.evaluate(()=>window.FT.results().length), 1, "למה זה חשוב");
})
```

הארגומנט השלישי של `eq`/`ok` הוא הודעת הכישלון. שווה להשקיע בה: היא
מה שמישהו יקרא בעוד חצי שנה כשהבדיקה תיפול.

## הערה על מהירות

ההרצה הראשונה של חבילת הדפדפן ארכה דקה לכל בדיקה. הסיבה: האפליקציה
מושכת גופן מ-`fonts.googleapis.com`, ובסביבת הבדיקות הבקשה נתקעה עד
לפקיעת הזמן במקום להיכשל מיד.

ההרנס חוסם כל בקשה שאינה לשרת המקומי. זה גם מקצר את ההרצה בסדר גודל
וגם בודק את המצב האמיתי: מורה במגרש, בלי קליטה. מאותה סיבה
ה-`service worker` חסום בבדיקות — הוא מוריד 6MB של תמונות למטמון בכל
הקשר חדש, ואין לו מה לתרום לבדיקה.

לכל בדיקה יש גבול של 60 שניות. בלעדיו בדיקה שנתקעת — למשל על פעולת
`IndexedDB` שנחסמה בגלל חיבור פתוח — משתקת את כל ההרצה בלי לומר איזו
בדיקה אשמה.
