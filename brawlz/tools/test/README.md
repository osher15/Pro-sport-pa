# בדיקות דפדפן

הבדיקות כאן רצות בדפדפן אמיתי (Chromium דרך Playwright) ובודקות את המשחק
בזמן ריצה. הן לא בדיקות יחידה — הן **מדידות**.

## הכלל

הרבה ממה שנשבר במשחק הזה לא נראה בקוד ולא נתפס בצילום מסך. כף רגל שמחליקה
2% נראית מושלמת בתמונה ומרגישה כמו ריחוף בתנועה. הדרך היחידה לדעת היא למדוד.

**לכן: כל טענה על התנהגות צריכה מספר.** אם אין דרך למדוד את זה — כותבים כלי
שימדוד, לפני שמתקנים.

## הרצה

```bash
# 1. שרת מקומי מתיקיית brawlz
cd brawlz && python3 -m http.server 8123

# 2. בטרמינל אחר
cd brawlz
npm i playwright            # פעם אחת
node tools/test/phase3d.js
```

משתני סביבה: `BRAWLZ_URL` (ברירת מחדל `http://localhost:8123`),
`BRAWLZ_EXE` (נתיב ל-Chromium), `BRAWLZ_SHOTS` (לאן נשמרים צילומים).

## מה כל אחת בודקת

| קובץ | מה נמדד | מה נחשב תקין |
|---|---|---|
| `phase3d.js` | שלבי המאץ׳, ניקוד, שמירה | הרג בספירה לאחור לא נספר · 30 שניות מזיזות את השעון 2:00→1:30 · ההרג החמישי מסיים |
| `cores3d.js` | הליבות | אש: חיים ×0.92 נזק ×1.1 · כבידה: יריב 190→105 מהירות · צל: נעלם אחרי 1.5ש שקט, נחשף בירי |
| `dash3d.js` | ששת האולטימייטים | רדיוס ונזק זהים ל-JSON · מרחק דאש בטווח 5% מהכוונה |
| `gait.js` | החלקת כף רגל | **פחות מ-3% מהמרחק שהגוף עבר.** מעל זה = ריחוף |
| `audio.js` | כל 20 הצלילים | אף אחד לא שקט · אף אחד לא נחתך · שיא בין 0.05 ל-0.28 |
| `phone.js` | מסגור המצלמה | פורטרט ≥ 9 אריחים לרוחב · לרוחב ≥ 15 |
| `single.js` | קובץ ההפצה הבודד | עולה, התפריט מלא, טקסטורות מפוענחות, אפס שגיאות |
| `verify2d.js` | גרסת הדו־ממד | עדיין עולה ומשחקת אחרי שינויים בליבה |

## הטעות שחוזרת

**אל תסמוך על `waitForTimeout` כדי לקדם את המשחק.** ברינדור תוכנה הדפדפן
מגיע ל-8 פריימים לשנייה, ו-`dt` חסום ב-1/20 — כלומר 5 שניות של שעון קיר
מקדמות את המשחק בפחות משנייה. חצי מ"הבאגים" שרדפתי היו הפער הזה.

**במקום זה:** `g.stop()` ואז `for (let i=0;i<60*seconds;i++) g.update(1/60)`.
דטרמיניסטי, מהיר, וחוזר על עצמו בדיוק.
