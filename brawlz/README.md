# BrawlZ: Cursed Arenas — אב־טיפוס מערכת קרב

אב־טיפוס רץ של מערכת הקרב הבסיסית: תנועה, תקיפה בסיסית, אולטימייט, מוות ורספאון —
כשכל משפטי הסלנג מתוך קובץ הדמויות מודפסים למסך (בועת דיבור מעל הדמות + פיד בצד)
וגם ללוג של הדפדפן.

הפרויקט הזה עצמאי לחלוטין ולא קשור לשאר הקוד בריפו.

---

## הפעלה

הדרך המומלצת — שרת מקומי, כדי שקובץ הנתונים ייטען כמו שצריך:

```
cd brawlz
python3 -m http.server 8123
```

ואז בדפדפן:

```
http://localhost:8123/index.html
```

אפשר גם פשוט לפתוח את `index.html` בדאבל־קליק. בדפדפן חוסם `fetch` על `file://`,
ולכן במצב הזה המשחק נופל אוטומטית לעותק המוטמע של הנתונים
(`data/characters.fallback.js`) ומדפיס על כך אזהרה בקונסולה.

המנוע Phaser 3.80.1 מצורף מקומית בתיקיית `vendor`, כך שהכול עובד גם בלי אינטרנט.

### שליטה

| פעולה | מקלדת | עכבר | מגע |
|---|---|---|---|
| תנועה | WASD / חצים | — | ג׳ויסטיק שמאל |
| תקיפה | J (אפשר להחזיק) | לחיצה שמאלית | כפתור כתום |
| אולטימייט | K או רווח | — | כפתור סגול |
| כיוון | — | הדמות מכוונת לסמן | לכיוון התנועה, ואם עומדים במקום — לאויב הקרוב |

## מבנה הקוד

```
brawlz/
├─ index.html                 שלד הדף + HUD בעברית (RTL)
├─ css/game.css
├─ data/
│  ├─ characters.json         ← מקור האמת. ה-JSON שלכם, בתוספת שדות אופציונליים
│  └─ characters.fallback.js  עותק מוטמע (נוצר אוטומטית) להרצה מ-file://
├─ src/
│  ├─ core/combat.js          מנוע הקרב — לוגיקה טהורה, בלי Phaser ובלי DOM
│  └─ game/
│     ├─ ArenaScene.js        הזירה: יצירת דמויות, קליעים, פידבק, אירועים
│     ├─ Fighter.js           הייצוג הוויזואלי של דמות + טיימינג אנימציות
│     ├─ ultimates.js         רג׳יסטרי האולטימייטים (לפי שם מה-JSON)
│     ├─ controllers.js       שליטת שחקן (מקלדת/עכבר/מגע) + בוט
│     ├─ hud.js               פאנלים ופיד המשפטים (DOM)
│     └─ textures.js          ארט זמני שנוצר בקוד — אין קבצי תמונה
├─ tools/sync-fallback.js
└─ vendor/phaser.min.js
```

### ההפרדה החשובה

`src/core/combat.js` לא יודע שקיים Phaser. הוא מחזיק את החוקים בלבד:

- `CombatActor` — HP, מהירות, זמני קירור, מצב (idle / attacking / ultimate / dead)
- `CombatSystem` — פותר תקיפות (`resolveMelee` בקונוס, `resolveAoe` ברדיוס),
  מפעיל נזק, הרג, ורספאון, ומשדר אירועים: `spawn`, `attack`, `damage`, `kill`,
  `death`, `ultimate`
- `VoiceDirector` — מאזין לאירועים ומוציא את משפט הסלנג המתאים מתוך ה-JSON

שכבת ה-Phaser רק מציירת ומזינה מיקומים פנימה. המשמעות המעשית: אפשר לבדוק את
חוקי הקרב בלי דפדפן, וגם לתרגם אותם 1:1 ל-C# אם תעברו ל-Unity — המבנה נשמר
(`CombatActor` → קומפוננטה, `CombatSystem` → מנהל סצנה, רג׳יסטרי אולטימייטים →
`ScriptableObject` לכל אולטימייט).

## איך משפטי הסלנג מגיעים למסך

```
CombatSystem  →  אירוע  →  VoiceDirector  →  המשפט מה-JSON
                                            ├─ בועת דיבור מעל הדמות (Phaser)
                                            ├─ פיד בצד המסך (DOM, RTL)
                                            └─ console.log
```

| אירוע במשחק | המפתח ב-JSON |
|---|---|
| כניסה לזירה / רספאון | `spawn` |
| הרגת יריב | `kill` |
| מוות | `death` |
| הפעלת אולטימייט | `ultimate_cast` |

אין שום מיפוי קשיח לדמות מסוימת — הכול נקרא מ-`voice_lines`.

## הוספת דמות חדשה

מוסיפים אובייקט ל-`characters` ב-`characters.json` ומריצים:

```
node tools/sync-fallback.js
```

הדמות תופיע מיד במסך הבחירה ותהיה משחקת. שדות חובה: `id`, `name`, `category`,
`stats`, `ultimate`, `voice_lines`.

שדות אופציונליים שהוספתי מעל ה-JSON המקורי שלכם (לכולם יש ברירת מחדל):

| שדה | תפקיד |
|---|---|
| `name_he` | שם תצוגה בעברית ב-HUD ובמסך הבחירה |
| `theme.body` / `theme.accent` / `theme.trim` | צבעי הדמות בארט הזמני |
| `ultimate.damage` | נזק האולטימייט (ברירת מחדל: פי 4 מהנזק הבסיסי) |
| `ultimate.radius` | רדיוס הפגיעה |
| `ultimate.knockback` | עוצמת ההדיפה |
| `ultimate.shards` | מספר הרסיסים (ל-Gren-Yarn) |

אולטימייט עם שם שאין לו מימוש ב-`ultimates.js` יקבל אוטומטית פיצוץ AoE גנרי
סביב הדמות, כך שדמות חדשה משחקת מיד — ורק כשרוצים התנהגות ייחודית מוסיפים
פונקציה לרג׳יסטרי.

## מספרי הכוונון

הטבלה המרכזית נמצאת ב-`BrawlZ.TUNING` בראש `src/core/combat.js`:

- `speed` מה-JSON הוא מכפיל — `1.0` שווה 190 פיקסלים לשנייה
- מגע: טווח 110px, קונוס 120°, קירור 0.6 שנ׳
- ירי: טווח 620px, קירור 0.9 שנ׳, מהירות קליע 660
- רספאון: 4 שניות, ואחריו 1.2 שניות חסינות

**Smash Punch** — קפיצה של כ-345px קדימה ואז AoE ברדיוס 180 עם הדפסה חזקה.
**Gren-Yarn** — כדור צמר איטי שמתפוצץ ל-10 רסיסים רדיאליים, כל אחד עם פיצוץ קטן.

## מה נמדד בבדיקות

הרצתי את האב־טיפוס בדפדפן אמיתי (Chromium) עם בוט מול בוט, והמחזור המלא עובד:
נזק מגע, נזק ירי, שני האולטימייטים פוגעים במלוא הנזק, הרג → מוות → רספאון,
וארבעת סוגי המשפטים נורים.

שתי מסקנות איזון שכדאי לשים לב אליהן — הן נובעות מהמספרים ב-GDD, לא מבאג:

1. **הדמות המרוחקת חזקה משמעותית.** בקרב של 30 שניות סבתא רימון עשתה בערך פי 4
   נזק מהקנגורו. היא גם מזיקה יותר (450 מול 300) וגם לא סופגת בכלל בזכות הטווח.
   כדי לאזן, לדמות מגע צריך כלי סגירת מרחק בתקיפה הבסיסית, או נזק/מהירות גבוהים יותר.
2. **1200 נזק באולטימייט זה כ-48% מה-HP של הקנגורו וכ-67% מזה של סבתא.**
   פגיעה אחת משנה קרב לגמרי — שווה לשקול נזק נמוך יותר או קירור ארוך יותר.

## מה עוד לא נמצא כאן

האב־טיפוס מכוון למערכת הקרב בלבד. אין בו מצב רשת, התאמת יריבים, התקדמות, חנות,
קול, או ארט אמיתי — הדמויות הן צורות שנוצרות בקוד. שכבת הארט מרוכזת כולה
ב-`textures.js` כדי שהחלפה בספרייטים אמיתיים תיגע רק בקובץ אחד.

## תיקיית הארט

`art/source/character-sheet.png` — גיליון הדמויות המקורי (רשת 7 על 5).
`art/characters/` — 35 אריחים חתוכים, קובץ לכל דמות, בתוספת `manifest.json`
עם שמות בעברית ובאנגלית ו־`_contact-sheet.jpg` לזיהוי מהיר.

לחיתוך מחדש של גיליון אחר:

```
python3 tools/split-sheet.py <גיליון.png> <תיקיית-יעד> --cols=7 --rows=5
```

השמות נלקחים מ־`tools/names.json` כשמספר האריחים תואם. שים לב: כל אריח הוא
בערך 195 על 148 פיקסלים וכולל את הרקע של הסצנה — זה חומר ייחוס, לא ספרייט
מוכן למשחק.

### מתמונה שנוצרה ל-ספרייט עם שקיפות

```
python3 tools/dekey.py <תמונה או תיקייה> <תיקיית-יעד> --tol=48 --max=512
```

הכלי מזהה את צבע הרקע משולי התמונה, מוחק רק אזורים בצבע הרקע **שמחוברים לשוליים**,
מנקה גלישת צבע בקצוות, חותך לתוכן ומקטין. ההגבלה לאזורים מחוברים היא מה שמאפשר
לדמות ירוקה בעצמה (קקטוס, אננס, אוגר, זומבי) לשרוד קילוף על רקע ירוק.

אם נשארת הילה בצבע הרקע — להעלות את `--tol`. אם נאכלים חלקים מהדמות — להוריד אותו.

### חיבור ספרייט לדמות

מוסיפים שדה `sprite` לדמות ב-`characters.json` עם נתיב יחסי לקובץ:

```
"sprite": "art/sprites/kangaroo-boxer.png"
```

הספרייט מוצג גם בזירה וגם בכרטיס בחירת הדמות, ומתהפך אופקית לפי כיוון הכוונון.
דמות בלי השדה הזה ממשיכה לקבל את הארט הזמני שנוצר בקוד, כך שאפשר להחליף דמות
אחת בכל פעם. גם כשלון טעינה של קובץ נופל חזרה לארט הזמני במקום לשבור את המשחק.

הספרייטים מיוצאים בגובה התצוגה הסופי (130 פיקסלים), כדי שהקנה מידה ב-Phaser
יישאר 1 וגוף הפיזיקה יישאר בפיקסלים לא מוקטנים.

**שים לב:** טעינת תמונות דורשת שרת מקומי. בפתיחה בדאבל־קליק הדפדפן חוסם אותן
והמשחק חוזר אוטומטית לארט הזמני.

## הרוסטר הנוכחי

שש דמויות משחקות. לחמש מהן יש ארט אמיתי; סבתא רימון עדיין על הארט הזמני.

| דמות | חיים | נזק | טווח | אולטימייט |
|---|---|---|---|---|
| קיי.או. קנגורו | 2500 | 300 | מגע | Smash Punch — זינוק ופיצוץ |
| סבתא רימון | 1800 | 450 | ירי | Gren-Yarn — כדור שמתפוצץ ל-10 |
| קקטוס קאובוי | 2000 | 320 | ירי | Thorn Storm — טבעת קוצים |
| כריש סייבר | 1600 | 500 | ירי | Torpedo Dash — זינוק מהיר |
| עצלן סומו | 3000 | 380 | מגע | Belly Flop — נחיתת בטן |
| סמל מוצץ | 2100 | 280 | ירי | Quiet Hour — צעקה שדוחפת |

המספרים הם טיוטה ולא עברו איזון אמיתי. שים לב שארבע מהשש הן דמויות ירי, ובאב־טיפוס
הזה טווח שווה יתרון גדול — זו נקודת האיזון הראשונה שתצטרך לגעת בה.
