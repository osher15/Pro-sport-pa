# עורך וידאו ותמונות — BrawlZ

## מה באמת זמין בסביבה

לפני שמבטיחים משהו — אלה הכלים שקיימים:

| כלי | לְמה | הערה |
|---|---|---|
| Chromium + Playwright | צילום מסך, הקלטת וידאו של המשחק | `/opt/pw-browsers/chromium-1194/chrome-linux/chrome` |
| `ffmpeg` | חיתוך, המרה, GIF, כיווץ | נמצא תחת `/opt/pw-browsers/ffmpeg-1011` |
| Python + Pillow | עיבוד תמונה, כיווץ PNG, ספרייטים | |

**מה שאין:** אין כאן ייצור ארט מאפס ואין מודלים תלת־ממדיים. עיבוד ולכידה — כן.
יצירה — לא. להגיד את זה מראש, לא אחרי שמנסים.

## לכידת גיימפליי — הדרך שעובדת

Playwright מקליט וידאו של הדף. הבילד עצמאי, אז אפשר לטעון אותו כ־`file://`:

```js
const b = await chromium.launch({
  executablePath: '/opt/pw-browsers/chromium-1194/chrome-linux/chrome',
  args: ['--no-sandbox', '--use-gl=swiftshader', '--enable-unsafe-swiftshader']
});
const ctx = await b.newContext({
  viewport: { width: 1280, height: 720 },
  recordVideo: { dir: 'out/', size: { width: 1280, height: 720 } }
});
```

**אזהרה:** הרינדור כאן הוא SwiftShader (תוכנה, לא GPU). קצב הפריימים יהיה
נמוך מהאמיתי. מתאים להדגמה ולבדיקה — **לא** לטריילר שמתיימר להראות ביצועים.
לטריילר אמיתי צריך הקלטה ממכשיר עם GPU.

## צילום מסך שכדאי להראות

- לתפוס **רגע**, לא מצב מנוחה: אולטי באוויר, שני שחקנים בטווח, ספירה לאחור
- לחכות שהזירה תסיים לטעון (`waitForTimeout` נדיב) — אחרת מצלמים מסך ריק
- 1280×720 לדסקטופ; לצילום "נייד" להשתמש בוויוופורט של טלפון בלנדסקייפ
- להסתיר את כפתורי הדיבאג (`תפריט` / `מחדש`) אם הצילום מיועד להצגה

## GIF ל־Slack ולשיתוף

```
ffmpeg -i in.webm -vf "fps=15,scale=480:-1:flags=lanczos,split[a][b];\
[a]palettegen[p];[b][p]paletteuse" -loop 0 out.gif
```

מתחת ל־2MB, מתחת ל־10 שניות, לולאה שסוגרת את עצמה. GIF ארוך לא נצפה.

## טקסטורות — כיווץ בלי לשבור

הטקסטורות הן 512×512 PNG, ~325KB כל אחת, ומוטמעות `base64` בבילד — כלומר
**כל קילובייט מתנפח בערך ב־33% בקובץ הסופי**. הבילד התלת־ממדי כבר 2MB.

לפני כיווץ: להסתכל על התמונה. אחרי: להשוות. `quantize` על טקסטורה של אריח
חוזר יכול לייצר פסים שנראים רק כשהאריח משוכפל על הרצפה.
